# 06 - 烘焙光照 (Baked Lighting)

## 课程概述

本课程介绍如何使用 Blender 烘焙光照并应用到 Babylon.js 场景中。烘焙光照是一种预先计算光照和阴影的技术，可以显著提升性能和视觉质量。

### 核心优势

| 优势 | 说明 |
|------|------|
| **性能提升** | 无需运行时计算光照和阴影，节省 GPU 资源 |
| **视觉质量** | Blender 的光照系统比实时渲染更精细 |
| **复杂光照** | 可以烘焙全局光照 (GI)、环境光遮蔽 (AO) 等效果 |

### 主要限制

- 仅适用于静态场景（物体不能移动）
- 阴影和光照固定在贴图中，无法动态改变
- 适合建筑可视化、静态展示等场景

## 核心知识点

### 1. 烘焙光照原理

**什么是烘焙光照？**

烘焙光照是将光照信息预先计算并存储到纹理贴图中的过程。在渲染时，直接从贴图中读取光照数据，而不是实时计算。

```
传统实时光照流程：
场景设置 -> 光源计算(每帧) -> 阴影计算(每帧) -> 渲染

烘焙光照流程：
Blender中设置 -> 烘焙光照 -> 生成纹理贴图 -> Babylon.js加载 -> 直接渲染
```

**为什么选择烘焙光照？**

1. **性能**：消除实时光照计算开销
2. **质量**：使用 Blender Cycles 的高质量光照
3. **效果**：可以包含全局光照、环境光遮蔽等复杂效果

### 2. UV 映射与纹理图集

**UV 映射概念**

UV 是将 3D 模型表面展开到 2D 平面的坐标系统，用于纹理贴图。

**纹理图集 (Texture Atlas)**

将多个物体的 UV 合并到一张大图中，实现：
- 减少纹理切换次数
- 提高渲染效率
- 统一材质管理

**UV 岛 (UV Islands)**

每个独立的 UV 区域称为一个"岛"。排列时需要：
- 避免重叠
- 保持间距（Margin）
- 最大化空间利用率

### 3. Blender 烘焙流程

#### 步骤 1：创建烘焙图像

1. 打开 UV Editor
2. Image -> New
3. 设置参数：2048x2048，32-bit Float
4. 保存为 Radiance HDR 格式

#### 步骤 2：创建 UV 映射

1. 选择物体 -> Object Data Properties -> UV Maps
2. 点击 + 创建新的 UV Map
3. 命名为 "joined"

#### 步骤 3：合并 UV 岛

1. 选择所有物体 -> 进入 Edit Mode
2. UV -> Pack Islands（自动排列）
3. 手动调整避免重叠

#### 步骤 4：设置材质

1. 打开 Shader Editor
2. 添加 Image Texture 节点
3. 选择烘焙图像

#### 步骤 5：烘焙设置

- Render Engine: Cycles
- Sampling: 256+
- Bake Type: Combined
- Margin: 8 pixels

#### 步骤 6：颜色管理

使用 Compositor 应用颜色管理设置，保存为 JPEG 格式。

## 代码示例与解释

### 关键代码说明

| 代码 | 说明 |
|------|------|
| camera.minZ = 0.01 | 设置近裁剪平面，允许近距离观察烘焙细节 |
| camera.speed = 0.1 | 降低移动速度，适合精细观察 |
| 无光源创建 | 烘焙光照不需要实时光源 |

## 最佳实践

### 1. 纹理大小选择

- 1024x1024：简单场景、移动端
- 2048x2048：大多数场景
- 4096x4096：高细节需求

### 2. UV 排列优化

- 最大化利用纹理空间
- UV 岛之间保持 8-16 像素边距
- 重要物体分配更多 UV 空间

### 3. 适用场景

- 建筑可视化
- 产品展示
- 静态游戏场景
- 虚拟博物馆

## 常见问题

### Q1: 烘焙后物体可以移动吗？

不可以。烘焙光照将阴影固定在纹理中，仅适用于静态场景。

### Q2: 如何避免 UV 岛之间的颜色溢出？

设置适当的 Margin 值（推荐 8-16 像素）。

### Q3: 烘焙纹理应该使用什么格式？

烘焙时使用 Radiance HDR，最终使用 JPEG (90%)。
